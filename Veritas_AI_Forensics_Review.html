High-Level Forensic Architecture

Veritas-AI (also referenced in codebase as Aegis-AI) is an enterprise-grade biometric analysis framework built for forensic investigators. The system aligns faces via MTCNN Aligner modules and pipes spatial features, reconstruction residuals, and frequency magnitudes through ML classifiers to distinguish between real camera-sensor captures and AI-generated fabrications.

Pipeline Architectures Comparison

The Veritas-AI system separates logic into three distinct pipelines to handle production inference speed constraints, legacy weighting checks, and deep learning research models:

Active Production
Pipeline A: XGBoost
  • Philosophy: Optimized real-time inference without running heavy neural networks on every request.
  • Model Structure: 9 Scalar biometric metrics are derived from the crop and classification is handled by gradient-boosted decision trees.
  • Model Files: fusion_engine_best.json (Trees) and scaler.json (Standardizer).
  • Latency: Fast (< 150ms post face detection).
R&D Deep Neural
Pipeline B: V2 Multi-Modal
  • Philosophy: Heavy neural transformer model mapping multiple domains.
  • Structural Pillars: Spatial (Swin-T), Frequency (ResNet-18 FFT), Latent (Auto-encoder reconstruction error mapping), and Statistical (LBP multi-layer perceptron).
  • Fusion strategy: 8-Head Multi-Head Cross-Attention using Spatial features as Query.
  • Loss Formulation: Compound Binary Cross Entropy + Supervised Contrastive Loss.
Legacy Ensemble
Pipeline C: Heuristic Weight
  • Philosophy: Traditional weighted combination of models.
  • Combination method: Weighted aggregation across static classifiers: EfficientNet-B3, external APIs, and manual FFT features.
  • Static weights: 40% External API, 40% custom classifier model, 10% FFT energy, 10% structural entropy.
  • Status: Deprecated in favor of Pipeline A.

Security & Deployment Configuration

Gateway Security Framework

  • Login Lockout Gate: Limits failed authentication entries. Tracks IPs in-memory; 5 bad attempts will lock out the IP address for 5 hours.
  • SSO Verification: Google JWT integration checks tokens natively on backend through the google.oauth2.id_token.verify_oauth2_token workflow.
  • Username Cool-down: Changes are capped at 1 change per 7-day period to prevent active identifier masking.
  • Admin Gatekeeping: User database views and deletions are restricted strictly to account email address adityajadhav300405@gmail.com.

Hugging Face Spaces & Docker Mappings

  • ProxyFix Configuration:Mounter sets ProxyFix(app.wsgi_app, x_for=1, x_proto=1, x_host=1, x_prefix=1) ensuring cookie parameters like Secure=True execute behind HF's SSL proxies.
  • SameSite Cookies: Handles cross-origin frame cookies. Modifies cookie headers to SameSite=None and Secure=True inside active user contexts.
  • Folder permissions: Pre-creates directories static/uploads and database storage path instance and runs chmod -R 777 to bypass HF variables UID constraints.
  • CPU Core Fallback: Configures Torch locks (--index-url https://download.pytorch.org/whl/cpu) to bypass standard GPU sandbox limitations on free tiers.
